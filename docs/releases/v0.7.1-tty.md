# v0.7.1-tty — the fixes that did not make v0.7

A maintenance release. The kernel and the device tree are **unchanged**
from v0.7-tty; the image carries four fixes that landed in the tree after
v0.7 shipped and were too useful to wait for a bigger release.

The visible ones: **HDMI audio now plays**, and a cold boot without a
network no longer starts nineteen days in the past. Neither was true of
the v0.7 download.

## What changed since v0.7

### 1. The clock fallback is refreshed by the build

The box has no battery-backed RTC. `fake-hwclock-load.service` restores
`/etc/fake-hwclock.data` early in boot, and chrony corrects from NTP once
the network is up. The build copied that file from the source tree
**without refreshing its contents**, so the v0.7 image carried
`2026-10-04 17:13:35` — nineteen days before the image was built. A cold
boot from the stick with no network started nineteen days in the past;
with the network up, chrony fixed it in seconds, which is why it was easy
to miss.

The build now derives the file's contents from `SOURCE_DATE_EPOCH`, so the
same tree still gives the same bytes. The fallback is the tree's
last-known time, not "now". The installer refreshes it to the install time
on the eMMC. See [`../time.md`](../time.md).

### 2. The hostname resolves locally

The vendor's `/etc/hosts` has `127.0.0.1 tvbox` and no entry for the
hostname, so `hostname -f` and `getent hosts eon-sc2` failed with
`Name or service not known` — anything wanting the local FQDN broke. The
build now adds `127.0.1.1 eon-sc2`, and the smoke test checks it. See
[`../network.md`](../network.md).

### 3. HDMI audio is routed at boot

The HDMI transmitter's `HDMITX Audio Source Select` defaults to `Spdif`,
but the playback path is TDM-C (`Tdm_C`, the `i2s2hdmi` device at
`hw:0,2`). With the default, a stream on `hw:0,2` runs and is **silent**.
The image now ships `eon-hdmi-audio.service`, which sets the source to
`Tdm_C` and unmutes the output at boot.

**Heard on the television, 2026-10-23:** a 440 Hz sine on `hw:0,2`
(48 kHz, S16_LE, stereo) is audible with `Tdm_C` and inaudible with the
default. See [`../audio.md`](../audio.md).

### 4. The smoke test ships in the image

`/root/smoke-test.sh` checks the things a build cannot: the branding on
the box, the console arrangement, failed units, the absence of a desktop,
`dpkg --audit` and `apt-get check`, the kernel and DTB on the boot
partition against their expected hashes, and the running system. One
command after every kernel or image change. It is a required path in the
manifest.

### 5. The vendor's login-message files are removed

The build used to remove only the vendor's **symlinks** into
`/usr/lib/qubian/update-motd.d/`. Some trees carry the same hooks as
**regular files** named `01-quban-header` and `15-qubian-system-state`,
and those survived. They contain the vendor's name in their comments, so
the smoke test failed the branding check on the first hardware boot. The
build now removes them by name and installs only `01-eon-header` and
`15-eon-system-state`.

### 6. The fontconfig cache unit no longer ships

`fontconfig-cache.service` was installed and enabled from
`scripts/overrides/`, but the TTY image has no fontconfig and no
`/usr/bin/fc-cache`, so it failed at boot with `status=203/EXEC`. That is
the second failure the first hardware boot found. The unit belongs with
the optional desktop set; the TTY image no longer installs or enables it.

## What is not fixed

- **The desktop.** Still frozen; it returns as an optional package set,
  not a second image.
- **WiFi.** The module **is present** on the board and worked under
  Android, but on Linux the SDIO bus finds no card, even though the DTB,
  pinmux, power GPIO and 32 kHz LPO PWM all match the Android setup. This
  is a vendor Linux bring-up gap, not missing hardware. Recorded for P3.
- **HDCP.** About twelve lines per boot end in `TX no hdcp key`: the
  vendor's HDMI TX has no HDCP key. Harmless for this image.
- **U-Boot networking.** Broken on this board; recovery is the stick or
  the serial tools.
- **The published password.** `root` / `tvbox`. Change it with `passwd`.
- **The vendor's kernel package (85 MB) is still in the image.** It can be
  purged on an installed box, but not in the build: the build host is
  x86_64 and cannot `dpkg` an ARM64 database. The image-level fix is a
  package-list rootfs. See
  [`../../manifest/vendor-leftovers.txt`](../../manifest/vendor-leftovers.txt).

## Last verified

**2026-10-23/24**, on the development box (EON SDSTB02, S905X4):

- **HDMI audio**: heard on the television after setting
  `HDMITX Audio Source Select` to `Tdm_C`; the boot unit that does it was
  installed, enabled, and survived a cold reboot.
- **Hostname**: `hostname -f` returns `eon-sc2`; `getent hosts eon-sc2`
  returns `127.0.1.1`.
- **Smoke test**: 24 checks, 0 failures, on the eMMC system.
- **Clock**: the arrangement is documented; the built image's fallback has
  not yet been watched on a boot without a network.
- **First v0.7.1 hardware boot**: the text console came up from the
  stick, the root was `/dev/sda2`, and the smoke test found two failures
  (§5 and §6). This rebuild removes both causes.

The **first v0.7.1-tty image file was written to a stick and booted.**
That boot is what found the two failures in §5 and §6: the vendor's
regular MOTD files were still present, and the fontconfig unit failed
with `status=203/EXEC`. Both are fixed in this rebuild.

The **rebuilt image has not been booted yet.** It is proven by the
manifest check and by `--check`, and by the first boot's discovery of the
two problems it removes. Write it to a stick and boot it once before
treating the download as exercised end-to-end.
