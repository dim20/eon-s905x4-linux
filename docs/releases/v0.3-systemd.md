# v0.3-systemd

A stick image you can `dd` and boot, and a box that comes up as a **real
multi-user Linux system** — systemd as PID 1, with `apt`, services and a
journal — on both the stick and the eMMC.

## The image

| | size | filesystem | contents |
|---|---|---|---|
| p1 | 64 MB | FAT32 (LBA), LBA 32768 | `Image`, DTB, `aml_autoscript` |
| p2 | 800 MB | ext4, LBA 163840 | the Debian rootfs — a working live system |

880 MB uncompressed, so it fits a **1 GB stick**. The rootfs has `chrony`,
`curl`, `openssh-server` and `ca-certificates` already installed, so there is
no package management to do before you can use the network.

Write it to a stick:

```sh
gunzip -c eon-s905x4-linux-stick.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
sync
```

Then plug it in and power cycle. The box boots the stick, brings up
networking and SSH, and gives you a login as `root` / `tvbox`.

To provision the eMMC, run `/root/install-to-emmc.sh` over SSH. It verifies
every artefact before and after writing, grows the filesystem to fill the
eMMC, and sets the boot command so the box boots on its own afterwards.
**Remove the stick and power cycle** to confirm.

If your stick is larger than 1 GB and you want the extra space in the live
system, run `scripts/grow-stick.sh` against it first.

## What changed since v0.2-image

v0.2 was a working image with a rescue-shell init. This one is a real OS.

- **systemd runs as PID 1**, on the stick and on the eMMC alike. 0 failed
  units, `apt-get update` works, the system reaches `running` rather than
  `degraded`, and it boots in about 7 seconds.
- **A U-Boot recovery window.** `bootdelay=3` gives a "Hit any key to stop
  autoboot" prompt on every boot. With a serial adapter and no USB stick
  attached, you can reach the U-Boot prompt and boot a different `init=` — the
  rootfs carries both systemd and a minimal `rescue-init.sh`. Change it with
  `fw_setenv bootdelay 0` for a faster boot.
- **The image no longer ships a machine-id.** systemd generates a unique one
  per box on first boot, so two boxes flashed from the same image are not the
  same machine.
- **The `chrony-wait` unit works.** This kernel has `CONFIG_USER_NS` unset,
  so systemd cannot set up a user namespace and the unit failed, leaving the
  system "degraded" with one failed unit. A drop-in disables `PrivateUsers`
  for that unit. See `scripts/overrides/`.
- **The installer takes `INIT=systemd|rescue`** to choose the init system,
  and sets `bootdelay` for you.
- **The rootfs `/dev` is correct.** The kernel initialises devtmpfs but does
  not mount it, so the rootfs must carry the directory the init mounts onto.
  Without it the box boots and then dies at the login prompt.
- **The stale `/boot` entry in `fstab` is gone**, along with the old
  vendor UUIDs.

## ⚠ Read this before you start

- **This is a test-box release.** It works on one development box. It has
  **not** been validated on any other hardware.
- **The default root password is `tvbox`.** Change it, or do not put the box
  on an untrusted network.
- **HDMI and audio have never been seen working.** DRM negotiates a 1080p60
  mode over EDID and the ASoC card registers, but nobody has looked at a
  screen or heard a speaker. Treat both as untested.
- **The first boot may need the vendor's own update path.** If your box does
  not find `aml_autoscript` on the stick by itself, you will need a UART
  console once — see [`docs/recovery.md`](https://github.com/dim20/eon-s905x4-linux/blob/main/docs/recovery.md).
- **The clock fallback is only unit-tested.** The chrony success path is
  proven on hardware; the "no network at boot" path has not been exercised on
  a real box.
