# v0.4-console

A stick image you can `dd` and boot — and this time the box gives you a
**text console on the TV**. Plug a display into the HDMI output and you get
a login prompt; no SSH, no serial cable, no UART adapter.

## What changed

### 1. A text console on the HDMI output

The kernel now has a framebuffer console, and it is bound to the framebuffer
that is actually scanned out to the display. On a real screen:

```
fbcon: mesondrmfb (fb4) is primary device
fbcon: Taking over console
Console: switching to colour frame buffer device 240x67
```

240×67 is 1920×1080 with an 8×16 font. You get a normal Linux console on
the TV: `root` and `tvbox` to log in, `passwd` to change the password,
`Ctrl-Alt-F1` and `Ctrl-Alt-F2` to move between terminals.

Three vendor bugs had to be fixed to get there, and they are worth knowing
about because they are the same shape as most of the rest of this project:

* **fbcon was not compiled in.** `CONFIG_FRAMEBUFFER_CONSOLE` was off in the
  vendor defconfig. The code was all there.
* **fbcon bound to the wrong framebuffer.** `con2fb_map_boot` is a static
  array, so it is zero-initialised — which silently means "framebuffer 0" —
  and framebuffer 0 is one of the vendor's OSD overlays. Their buffers live
  in a reserved-memory region that is not in the kernel's direct map, so the
  console's blitter wrote to an unmapped address and the machine oopsed.
* **Even bound to the right framebuffer, nothing was displayed.** The DRM
  framebuffer took its size from a CRTC that had no mode yet at probe time,
  so the size was zero, and the plane was programmed with a zero-sized
  source rectangle.

The patch is in the repository as
`patches/0003-console-bind-to-display.patch`.

### 2. No desktop in the image, and the build enforces it

Neither XFCE nor LightDM is part of the image, and neither is any other
desktop or display manager. That was already true; what is new is that the
image build **refuses to produce an image that contains one**:

```
[build-image] ERROR: the source tree has lightdm installed.
```

A display manager takes the framebuffer away from the text console, and a
desktop is 450 MB of packages that you may not want. The build also
requires `tasksel` to be present, so `tasksel` always offers XFCE, GNOME,
KDE, LXDE and LXQt.

### 3. The rootfs is owned by root

The v0.3 image's files were owned by uid 1000 rather than uid 0 — every
binary, every config file, `/etc/shadow` included. It worked, because
nothing on the system was owned by uid 1000, but it was wrong: a file
owned by an unprivileged uid is not a system file.

This release fixes it. Verified in the built image:

```
/bin/bash          User: 0  Group: 0
/etc/shadow        User: 0  Group: 0
/etc/passwd        User: 0  Group: 0
/root              User: 0  Group: 0
```

## The image

| | size | filesystem | contents |
|---|---|---|---|
| p1 | 64 MB | FAT32 (LBA), LBA 32768 | `Image`, DTB, `aml_autoscript` |
| p2 | 800 MB | ext4, LBA 163840 | the Debian rootfs — a working live system |

880 MB uncompressed, so it fits a **1 GB stick**. The rootfs has `chrony`,
`curl`, `openssh-server`, `ca-certificates` and `tasksel` already installed.

Write it to a stick:

```sh
gunzip -c eon-s905x4-linux-stick.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
sync
```

Then plug it in and power cycle. The box boots the stick, brings up
networking and SSH, and gives you a login as `root` / `tvbox` — on the
serial console, over SSH, **and on the TV**.

## Installing it to the eMMC

From the live system (which is what the stick boots):

```sh
/root/install-to-emmc.sh
```

It verifies every artefact before and after writing, grows the filesystem to
fill the eMMC, and sets the boot command so the box boots on its own
afterwards. **Remove the stick and power cycle** to confirm.

The installer sets a conditional boot command: with the stick plugged in the
box boots the stick, so the stick remains a recovery key; with it removed the
box boots the eMMC on its own.

## Known limitations

These are unchanged from v0.3, except where noted.

1. **Audio has never been confirmed audible.** The ASoC card registers and
   the HDMI transmitter reports a valid audio format, but nobody has heard a
   speaker.
2. **No desktop in the image.** Deliberate — see above. `tasksel` installs
   one. If you do, expect the first paint to take about 90 seconds: the
   vendor's DRM driver never delivers a vblank interrupt, so X's atomic
   commit waits out a 100 ms timeout, warns, and the kernel oopses, which
   can kill Xorg. On the TV that shows up as a **frozen picture** rather
   than as a crash message. The text console is unaffected, because it does
   not do a flip and so never waits for a vblank.
3. **No GPU-accelerated 3D.** The vendor DRM driver advertises no dma-buf
   modifier support, so Mesa's GBM has nothing to negotiate and `kmscube`
   fails. A 2D desktop is unaffected.
4. **The clock fallback is only unit-tested.** The chrony success path is
   proven on hardware; the "no network at boot" path has not been exercised
   on a real box.
5. **The default root password is `tvbox`.** Change it from the console —
   the HDMI one or the SSH one — before you put the box on a network you do
   not trust.
6. **Only one box has been tested.** Everything here was proven on one
   development box. It has not been tested on any other hardware.
7. **The first boot may need the vendor's own update path.** If your box does
   not find `aml_autoscript` on the stick by itself, see
   [`docs/recovery.md`](docs/recovery.md) — you will need a UART console once.
