# v0.2-image

A stick image you can `dd` and boot. This is the release where the project
becomes usable by someone else: one file, one `dd`, and the box comes up as
a logged-in Debian system.

## The image

| | size | filesystem | contents |
|---|---|---|---|
| p1 | 64 MB | FAT32 (LBA), LBA 32768 | `Image`, DTB, `aml_autoscript` |
| p2 | 800 MB | ext4, LBA 163840 | the Debian rootfs — a working live system |

880 MB uncompressed, so it fits a **1 GB stick**. The rootfs has `chrony`,
`curl`, `openssh-server` and `ca-certificates` already installed, so there is
no package management to do before you can use the network.

Write it to a stick:

```sh
gunzip -c eon-s905x4-linux-stick.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
sync
```

Then plug it in and power cycle. The box boots the stick, brings up
networking and SSH, and gives you a login as `root` / `tvbox`.

To provision the eMMC, run `/root/install-to-emmc.sh` over SSH. It verifies
every artefact before and after writing, grows the filesystem to fill the
eMMC, and sets the boot command so the box boots on its own afterwards.
**Remove the stick and power cycle** to confirm.

If your stick is larger than 1 GB and you want the extra space in the live
system, run `scripts/grow-stick.sh` against it first.

## What changed since v0.1-testbox

v0.1 was a kernel and a device tree, and a set of instructions to provision
a box by hand. This release is a working image plus an installer that does
the whole job.

- **The stick image itself.** v0.1 shipped no image — you had to build one.
  This is a complete, bootable, installable stick.
- **The installer runs end-to-end.** It partitions and formats the eMMC,
  copies the rootfs, **grows the filesystem to fill the partition**, restores
  the U-Boot environment, sets the boot command, and verifies every write
  from storage. The rootfs goes from 744 MB to 15 GB.
- **The boot command is installed automatically.** The installer locates the
  U-Boot environment read-only, because the stock configuration on this
  hardware names a device that does not exist and the wrong offset. If it
  cannot positively verify the environment, it refuses to touch it rather
  than risk writing somewhere uncertain.
- **A conditional boot command.** The stick is a recovery key, not a
  dependency: plug it in and the box boots the stick, unplug it and the box
  boots the eMMC. No menu, no countdown, no wrong-default failure mode.
- **Networking, clock and SSH** now work unattended after a cold boot.
- **The clock has a fallback.** A persisted last-known-good time is restored
  when chrony cannot sync, so a boot with no network is not stuck at 1970.
- **Flat boot partition.** The kernel and DTB are at the root of the boot
  partition rather than in a `d/` subdirectory.

## ⚠ Read this before you start

- **This is a test-box release.** It works on one development box. It has
  **not** been validated across a fleet, and the eight other boxes are
  sealed and untouched.
- **The default root password is `tvbox`.** Change it, or do not put the box
  on an untrusted network.
- **HDMI and audio have never been seen working.** DRM negotiates a 1080p60
  mode over EDID and the ASoC card registers, but nobody has looked at a
  screen or heard a speaker. Treat both as untested.
- **The first boot may need the vendor's own update path.** If your box does
  not find `aml_autoscript` on the stick by itself, you will need a UART
  console once — see [`docs/recovery.md`](https://github.com/dim20/eon-s905x4-linux/blob/main/docs/recovery.md).
- **The clock fallback is only unit-tested.** The chrony success path is
  proven on hardware; the "no network at boot" path has not been exercised
  on a real box.
