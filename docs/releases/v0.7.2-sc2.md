# v0.7.2-sc2 — SC2 Linux

The rename release. The product, the repository and every name a user
sees are now **SC2 Linux**; the box and the kernel are the same. The
kernel image and device tree are **byte-identical** to v0.7.1-tty. The
image differs only in branding and in the names of the files that carry
it.

Releases up to and including `v0.7.1-tty` were published under the earlier
**EON Linux** name. They remain valid historical artefacts. This is the
first release under the SC2 Linux name.

**Status: built and manifest-checked. The hardware smoke test has not been
run yet. Do not publish this release until it passes.**

## What changed since v0.7.1-tty

### 1. The product and repository are named SC2 Linux

The GitHub repository is now `dim20/sc2-linux`. GitHub preserves
redirects from the old URL, so existing links and clones keep working.
The product name in the documentation, the release assets and the login
files is **SC2 Linux**.

The hardware is still the **EON SDSTB02** (Amlogic S905X4 / SC2): "EON"
is the vendor's brand and remains the correct name for the box. It is no
longer used as the product name.

### 2. The login files carry the new name

`/etc/eon-release` is now `/etc/sc2-release`. `/etc/issue`,
`/etc/issue.net`, the two MOTD hooks and the HDMI-audio unit are renamed
to `sc2-*`, and their contents say **SC2 Linux**. The old EON-named files
are removed from a tree that was built before the rename, so a rebuilt
image cannot carry both identities.

The hostname changes from `eon-sc2` to `sc2`, and `/etc/hosts` maps
`127.0.1.1 sc2` instead of the old name. The build removes the stale
mapping from a tree that still has it.

### 3. The kernel package is `sc2-kernel`

The package name, the installed path (`/usr/lib/sc2-kernel/...`), the
tools (`sc2-kernel-list`, `sc2-kernel-select`) and the maintainer field
now use `sc2`. The built file is
`linux-image-sc2_5.4.210-sc2_arm64.deb`.

The kernel's own `uname -r` is the vendor tree's string and does **not**
change; the package version (`5.4.210-sc2`) is the project's label. See
[`../kernel-package.md`](../kernel-package.md) for why the two differ.

### 4. The checks and documentation follow the name

`manifest/forbidden-strings.txt` now forbids **EON Linux** as a product
name in the login files. `scripts/check-docs.sh` checks the new override
names. `scripts/smoke-test.sh` expects `/etc/sc2-release`, the SC2 Linux
banner and, when installed, the `sc2-kernel` package. The inventory and
required-path manifests were updated to match.

## What did not change

- The kernel and device tree: byte-identical to v0.7.1-tty.
- The image's behaviour: unattended boot from eMMC and from the stick, the
  text console on HDMI and serial, HDMI audio, the clock fallback, the
  hostname fix and the smoke test are the same as v0.7.1-tty.
- The hardware: the same EON SDSTB02 / Amlogic S905X4 box.

## What is still broken, or not yet proven

- **The hardware smoke test for v0.7.2 has not been run.** The automated
  build and manifest checks passed (181 checks); the branding and hostname
  changes still need to be seen on the box. Until then this build is not a
  published release.
- **WiFi**: no open driver for the RTL8812CS. Unchanged from v0.7.1-tty.
- **The image does not install `sc2-kernel` into its own rootfs.** The
  kernel ships on the boot partition and the package is a separate
  artefact. `/root/smoke-test.sh` warns when the package is absent; it does
  not fail. Install the package with `dpkg -i` when you want rollback.
